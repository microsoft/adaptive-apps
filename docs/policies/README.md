# Policies

There are many policy systems that focus on enforcing controls over different aspects of a system. For example, [Microsoft Purview](https://learn.microsoft.com/en-us/purview/purview) focuses on data governance and data loss prevention, [Agent Governance Toolkit](https://github.com/microsoft/agent-governance-toolkit) focuses on governed agent behavior, [Open Policy Agent (OPA)](https://www.openpolicyagent.org/) provides general-purpose policy decisioning, and [Kyverno](https://kyverno.io/) focuses on Kubernetes-native admission control, validation, and mutation policies.

Adaptive App adopts OPA as the default cross-cutting policy decision engine and uses [Gatekeeper](https://open-policy-agent.github.io/gatekeeper/website/)-compatible policy patterns for Kubernetes admission control. On AKS, this aligns with [Azure Policy](https://learn.microsoft.com/en-us/azure/governance/policy/overview) for Kubernetes, which builds on Gatekeeper to provide centralized policy assignment and compliance reporting. On non-AKS clusters, upstream Gatekeeper can provide similar Kubernetes-native enforcement. Adaptive App also provides guidance and reference integrations for using OPA with components such as [LiteLLM](https://docs.litellm.ai/docs/) and service mesh enforcement points.


This choice does not preclude the use of other policy engines in parallel or in conjunction with OPA. In practice, organizations may combine multiple policy systems, each operating at the layer where it provides the most value. For example, Purview may provide data classification and DLP signals, Kyverno may manage Kubernetes object validation and mutation, Agent Governance Toolkit may enforce agent-level controls, and OPA may serve as a common policy decision point across application, gateway, and runtime enforcement scenarios.
